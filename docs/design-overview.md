# 設計概要 — Qorynth Distributed Key Management System

> **状態:** 設計案 — 実装検証中

## 1. システム構成

OpenBaoのAuto-Unsealを最初のユースケースとし、将来的には署名・暗号化・復号などの汎用的な鍵管理基盤を目指します。

| コンポーネント | 台数 | 役割 |
|---|---|---|
| OpenBao | 3 | Secret管理・Raft |
| `qorynth-node` | 3 | 分散鍵管理・暗号処理 |
| `qorynth-seal` | 2 | OpenBao Auto-Unseal連携 |
| `qorynth-signal` | 3 | P2P接続確立 |
| `qorynth-approval` | 論理サービス | 端末承認・状態管理 |
| 承認端末 | 5以上 | 3-of-5による有効化 |
| `qorynth` CLI | 任意 | 管理・監視・復旧 |

## 2. 基本動作

1. Qorynthノードが起動し、P2P接続を確立する。
2. 鍵利用は`LOCKED`状態で開始する。
3. 登録されたPC・スマホのうち3台以上が有効化を承認する。
4. 承認成立後、クラスタが`ACTIVE`に移行する。
5. OpenBaoはQorynth経由でAuto-Unsealを実行する。
6. OpenBaoだけが再起動した場合、QorynthがACTIVEなら再承認なしで復旧する。

通常時はAuto-Unseal、HSMクラスタの有効化時のみ3台承認という構成です。

## 3. セキュリティ設計

| 項目 | 方針 |
|---|---|
| 鍵保護 | 2-of-3閾値暗号 |
| 端末承認 | 3-of-5、WebAuthn / Passkey |
| ノード認証 | mTLS + TPM 2.0 |
| ノード通信 | QUIC / TLS 1.3 |
| 盗難対策 | 鍵分散・ノード失効・起動時ロック |
| 状態同期 | Raft |
| バックアップ | 暗号化・分散・オフライン復旧 |
| 管理 | 固定された中央管理ノードなし |

**重要な区別:**
- 鍵利用の2-of-3と、有効化承認の3-of-5は独立した仕組み
- Qorynthノード1台とOpenBaoノード1台が盗まれた場合、盗難機器だけではSeal鍵を復号できないことを目標
- 稼働中のOpenBaoのメモリに存在する鍵・Secretまでは保護できない（これは想定範囲内）

## 4. 障害・再起動時の動作

| 状況 | 期待動作 |
|---|---|
| OpenBao 1台停止 | 残り2台で継続 |
| OpenBao全台再起動 | QorynthがACTIVEなら自動復旧 |
| Qorynth 1台停止 | 残り2台で鍵処理を継続 |
| Signaling 1台停止 | 他のSignalingを利用 |
| Signaling全台停止 | 既知Peer間の通信は継続可能 |
| Qorynth全台再起動 | LOCKEDに戻り3台承認が必要 |
| Qorynth 1台盗難 | ノード失効・鍵Share更新 |
| 鍵データ喪失 | 分散バックアップから復旧 |

**未確定:** Qorynthの1台だけが再起動した場合の再参加・再有効化ルールは、今後詳細化する。

## 5. 開発方針

推奨リポジトリ: `kigawa-net/qorynth`

実装順序:

1. P2P通信と冗長Signaling
2. ノード認証・クラスタメンバーシップ管理
3. 3-of-5端末承認
4. HSM有効化状態管理
5. 閾値暗号による分散鍵処理
6. OpenBao Auto-Unseal連携
7. 鍵バックアップ・復旧・盗難時失効

## 6. 未確定の重要事項

| 項目 | 状況 |
|---|---|
| 閾値暗号方式 | 2-of-3分散復号のプロトコル選定が必要 |
| HSM実装 | 既製HSM利用かTPM独自KMSか |
| OpenBao連携 | PKCS#11互換か専用KMSプラグインか |
| 有効化状態 | ノード再起動時のロック状態とクラスタ全体のACTIVE状態の整合性 |
| バックアップ | 鍵Shareの安全な復元とローテーション |
| 盗難検知 | 盗難された正規ノードの再接続・鍵利用をどう阻止するか |

## 7. 最終目標

P2Pで協調する複数の鍵管理ノードが秘密鍵を分散保持し、3台以上のクライアント承認で鍵利用を有効化する、耐障害性・盗難耐性を備えた分散KMS。

現時点ではアーキテクチャ案であり、特に閾値暗号とOpenBao連携は実装・検証が必要です。
